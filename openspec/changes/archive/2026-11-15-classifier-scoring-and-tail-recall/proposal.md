# Proposal

Citation key: bare `D N`, `S N`, `O N` and `T N` codes refer to `michael-orientation.md`; `Chidi §n` and `Eleanor §n` to `research-chidi.md` and `research-eleanor.md`; Joel's own words by section in `owner-rulings.md`.

## Why

The archive half of taiknr works: a large tool output leaves the model's context as a one-line stub, and its raw text stays on the branch in a `taiknr-side-store` record. Nothing ever brings it back. Every body on the recall path is still a stub — `formatRecalledContext` and `recallRelevantContext` throw `Not implemented`, the Jev scorer adapter's `score` throws, the context adapter's two exports throw, the registration is `_pi.on("context", () => {})`, and the notifier the composition root passes has an empty `notifyOnce` (`Eleanor` §1; T7). A user who installs the package today pays the stubbing cost and gets no recall.

ADR 0002 wrote the mechanism down before anything measured it, and the orientation found the event wrong. Appending under `context` rebuilds the request's head whenever the session carries a mid-conversation system message, which drops the cached prefix on Joel's Opus 5.5 sessions at about $0.25 a flip against $0.0227 saved per request (T1; `Chidi` §1). The contract shapes were gated; that behaviour was never one. Joel ruled the card's open questions and this change implements recall on those rulings: `context_with_system`, a two-part cache key, a bounded single-attempt classifier call, a size bound that stops before the host's compaction threshold, and one notice that print mode simply cannot show.

## What Changes

- **Recall registers on `context_with_system`, not `context`** (S1; T1). The measured layout under `context_with_system` keeps the mid-conversation system message in place and its own tail per request; under `context` the patch is folded into a rebuilt head and the prefix is lost on models that accept mid-conversation system messages. The payload and result types are identical, `AgentMessage[]` and `ContextEventResult`, so the registration keeps the parameters, types and return type it has at `HEAD` (`Chidi` §1). This revises D8's event list, ADR 0002's mechanism 3 and `ARCHITECTURE.md` §3/§5, and takes an `extension-packaging` delta plus one new ADR narrowing ADR 0002 (S1; `AGENTS.md`).
- **The key is timestamp plus text, and one key is scored once while the archive's size is unchanged** (S8; ruling 6). Three requests in one tool-loop turn share a key; a second `continue` and a steer each get a new one, because steering builds a fresh `role: "user"` message with its own `Date.now()` (`Chidi` §2; T5). "Unchanged" means the store's `size()` equals its size at scoring, so an item landing at settlement or hydration under the same user message scores again (ruling 6). While the archive is empty or the request carries no user message, nothing is recalled and no call is made.
- **A steer moves the recall, and the earlier block drops** (Joel's "Orientation Q1" → (a); T5). Joel chose the least mechanism over keeping each message's recall until the run settles: the recall sits on the newest user message only, so the earlier message loses its block for the rest of the run, the prefix diverges at that message, and each steer in a run that recalled something costs one cache rewrite.
- **One classifier call per key, one `bool` question per eligible archived item** (S2; ruling 9). The questions are keyed by each item's whole entry id, passed opaquely (ADR 0006), and the state holds the prompt's text and each id's stub; eligibility is a filter applied before scoring, with one home, so an item another extension redacted and an item off the branch are never asked about (ruling 9). No raw archived text and no image is sent: what leaves for OpenRouter is the new prompt and each stub — the tool name, a 120-unit args summary and a 180-unit preview of the raw text — and never the full raw text (T13; ruling 11). What each question says follows the proof of concept and is the design's to settle (O4); the disclosure boundary — the prompt's text and the stubs, nothing else — is not.
- **The model and its timeout come from the session's resolved config, read at event time** (S3; D7). The provider and model id come from the two fields through the host's catalog lookup; no provider is hardcoded and there is no fallback id, which is what the proof of concept got wrong by silently falling back to `typesafe/jev-1.14` (T12). The call is bounded by the new config field, is attempted once with no retry, and carries `ctx.signal` so `Escape` ends it (`Chidi` §3; Joel's "Orientation Q2" → (b) and (c)).
- **A new config field bounds the wait.** Joel took both (b) and (c): a fixed timeout, no retries, and "a sensible default that can be overridden". Without it a hung classifier holds the user's request inside an awaited handler for up to the host's 300 s, and retries after a 429 can wait 60 s each (T3). The key is `classifierTimeoutMs`, an integer of milliseconds from 1 to 2147483647 defaulting to the value the design records from a measured Jev round trip — the measurement landed at a median of 241–248 ms and a maximum of 361 ms over ten calls, with no value recommended (`research-chidi.addendum.md`), and the number stays the design's.
- **Selection is the existing threshold rule** (S3). `selectRecalledIds` keeps its `>=`, and its pure test `tests/domain/recall.test.ts` is a Create rather than an existing file: no test names any of the three recall functions today (ruling 18). `decisionThreshold` keeps its default of 0.5, and `decisionThreshold: 0` — a valid setting — recalls every scored item (`development-checks` spec; `configuration` spec).
- **Recall keeps the request it builds at or under the host's compaction threshold** (Joel's "Orientation Q3" → (b); ruling 4). Whole items only, in descending probability, stopping before the request would pass the model's context window less its reserved tokens, so recall keeps the request at or under that threshold by pi's own estimate. The window, the reserve and the request's current size are read per request (ruling 4). The claim is not that no request this change builds triggers the host's overflow recovery: pi's estimate undercounts, so that residual risk — one persisted compaction, then a failed turn, if recovery does run (T9) — is assessed separately (D2). Nor does it claim that pi's next compaction check stays under the threshold: that check counts the provider usage of the last request, recall included, so a full recall can make pi compact at the next step or after the run (Joel's "Design review escalation — recall and pi's next compaction check", 2026-11-15); no taiknr setting avoids it while recall is on, and raising `decisionThreshold` narrows it (design decision 2). The bound lives in recall and puts no ceiling in the archive, so the archive-scaling card is not foreclosed (D5).
- **The recall block is one trailing text block on the latest user message** (S1). The message's existing blocks — including an image the prompt carried — stay where they are and the block follows them, which is what the proof of concept got wrong when it replaced the whole content with a string (T10; `Chidi` §2). Every other message is untouched, the leading system message included, and nothing is appended when nothing is recalled. The block's wording and its treatment of a raw text that contains its own delimiter are the design's (O4).
- **Recall yields to edits taiknr did not write, and to items off the branch** (S9). An item is eligible only while a tool-result entry with its id is on the active branch and the latest `context_edit` targeting it there has a non-null replacement whose first content block is taiknr's own stub — only that block is compared, because a settlement writes the stub's text block followed by the original non-text blocks (ruling 10). An item with no edit at all therefore has nothing to recall: its raw text was never replaced and is already in context (ruling 10). The check runs on every request, cache hits included, not once per scored key (ZO-2; ruling 8). A persisted `context_edit` redaction is never undone, and an item left on a branch behind an off → `/tree` → on sequence is never resurrected; a request-time transform by another extension, in `context` or in an earlier-loaded `context_with_system` handler, does not see the recalled text, and the classifier payload passes through no request-time transform at all (ADR 0005; T8; D14; ruling 11).
- **A failure fails open with one notice per session** (S4). A missing model, an answer whose stop reason is an error, and a call abandoned at its timeout each leave the request without recall and report at most one `ctx.ui.notify` warning, naming the provider, the model, the config field and the reason; only a user cancel comes back from the port as `undefined` and reports nothing, while every failure crosses it as a rejection whose message is the finished notice (T4; ruling 1). The flag lives in the notifier, built once at registration rather than per event, and `warned` is set only after `notify` returns, so a throw from a stale `ctx` cannot use up the session's single notice (D13; T7; ruling 3). A mistyped model name fails open the same way rather than turning taiknr off at session start (Joel's "Orientation Q4 sub-question" → (a)).
- **A timeout is a failure, not a hang** (T3; Joel's "Orientation Q2"). The request goes out without recall after the configured timeout, and the notice appears once.
- **The notice keeps the channel Joel chose** (Joel's "Orientation Q4" → (a)). `ctx.ui.notify` shows in the TUI and RPC modes and is a silent no-op in print and JSON (`Chidi` §4). Stubbing keeps working in every mode, which is why Michael's recommendation and Joel's answer both accept the silence there.
- **Inert while taiknr is off, verified through the gate** (D3; S5). With `enabled: false` or a rejected config there is no recall and no classifier call, enforced by the composition root's gate rather than a check inside the recall handler. This verifies the recall half of the two `configuration` scenarios the archive and recall cards were handed: a project file turning taiknr off for one project, and stubs made before the switch staying stubbed.
- **Recall writes nothing** (S1; T14). It changes the messages of the request it answers and nothing else: no session entry, no store write, no branch change, no printed line. Its per-session decisions stay in memory in `RecallCache`, which is what a readout would show, so the Status card can read them without a persistence change (D14). Nothing about recall is observable today except through the model's behaviour, and the design names how it is observed (O7).
- **The default suite never calls the classifier** (T2; S7; D10). `OPENROUTER_API_KEY` is set in Joel's shell and `ModelRuntime.create` still resolves it through an isolated `authPath`, so two existing session-level assertions would start billing live Jev calls and one would depend on its answer. Every session-level recall test removes the provider credentials from the environment, the classifier comes from a provider the test itself registers, and where an existing assertion would depend on the answer it scripts a "no" rather than being relaxed. No new dependency.
- **End-to-end verification is a live script run by hand** (Joel's "Orientation Q5" → (a)). It spends model calls, sits at the repository root outside the lint allowlist and the test include, and is what ticks the verification task; Joel's own manual test does not stand in for it. The gate's scope stays as `development-checks` fixes it, so no file there changes.
- **The docs pass follows the implementation and blocks nothing** (S11; D6). `AGENTS.md`, `README.md` (the field list gains `classifierTimeoutMs`), `ARCHITECTURE.md` (the intro, §3, §5 and §7, which today mention only the stubs and not the new data flow, T13) and one new ADR narrowing ADR 0002 are corrected after Michael approves the implementation. `README.md` and `ARCHITECTURE.md` §7 say plainly that prompts and stubs leave the machine by default, and that request-time redactors do not cover recall (ruling 11).

**Deliberately not in this change** (orientation §2; D2; D4 unless noted):

- The archive half: staging, settlement and hydration handlers, the `taiknr-side-store` format, the stub format and `InMemoryArchiveStore`'s write path. Recall only reads the store (ADR 0004).
- The Status and `/taiknr` cards. `SessionConfig.setEnabled` stays as it is, no `ctx.ui.setStatus` is added, and recall's decisions stay in `RecallCache` for that card to read (D14).
- A size ceiling, pruning or eviction in the archive, which the archive-scaling card owns (D5; Joel's "Orientation Q3").
- Calibrating the threshold from real recall quality, and Jev's recall quality itself, which needs a model call.
- The OpenRouter-provider abstraction behind `defaultDecisionModelProvider` (D4).
- A spend readout: Joel accepted the invisible cost until the Status card (Joel's "Orientation Q6" → (a)).
- Folding in Pi's usage figure undercount after a `context_edit` (D2).
- Any logger or `console.*`; observation goes through the named surfaces (D11).
- Serving a repeated tool call from the archive, which is a separate card (D6).
- Any change to `package.json`, `package-lock.json`, `biome.json`, `tsconfig.json`, `vitest.config.ts`, `jev-context-poc.ts` or `test-jev-poc.mjs`.
- A reuse path through `cli/` or `mcp/`. The classifier protocol stays inside the scorer adapter and caching and fail-open stay in a use case that knows nothing about pi (ADR 0001; S10).

## Capabilities

### New Capabilities

- `tail-recall`: when taiknr recalls archived outputs, how it scores them against the latest user prompt, what it appends and where, how far one recall may grow, and what it does when classification fails or taiknr is off.

### Modified Capabilities

- `configuration`: one new field, `classifierTimeoutMs` — its default, its override and its validation — so the classifier call can be bounded and a user can override the bound.
- `extension-packaging`: the seven registered events name `context_with_system` in place of `context`, because recall subscribes to the system-inclusive one. The registrar's parameters, types and return type are unchanged; the one contract difference `Signatures unchanged` gains is that the context registrar's dependency object drops its `notifier` member, because the notifier is built in the handler (ruling 3; ruling 12).

No other capability changes. `development-checks` already fixes the test include and the lint allowlist so that a root-level live script is neither collected, nor linted, nor type-checked, and its requirement that the suite makes no live model or classifier call already covers the test side. `archive-stubbing` and `configuration` already say what happens while taiknr is off; the two scenarios naming the recall card are verified here, and verifying them adds no requirement.

## Impact

- `src/infra/pi-event-handlers/context.ts`: the registration moves to `context_with_system` and gains the call into the use case; the handler builds the once-per-session notifier at registration and the scorer adapter per event from the holder's event-time config, and its dependency object loses `notifier` (ruling 3; ruling 12). The file and registrar names after that move are the design's (O8).
- `src/infra/adapters/pi-context-adapter.ts`: `extractLatestUserPrompt` and `appendRecalledContextToMessages` replaced with their bodies — the key, and the one trailing block with every existing block left in place.
- `src/infra/adapters/pi-jev-scorer-adapter.ts`: `score`'s body — the catalog lookup at event time, the single call, the question map, the abort signal and the timeout.
- `src/infra/adapters/pi-notifier-adapter.ts`: `createOncePerSessionNotifier` keeps its signature and gains its body — `warned` set after `notify` returns — with its `getCtx` returning the current event's `ctx`; it is built in the context handler, not the composition root, and its flag is per factory call (ruling 3).
- `src/use-cases/recall-relevant-context.ts`: `recallRelevantContext`'s body — the key, the in-memory cache, selection through the threshold, the size bound, and fail-open with the one notice.
- `src/domain/recall.ts`: `formatRecalledContext`'s body. `selectRecalledIds` and its `>=` stay exactly as they are; `tests/domain/recall.test.ts` is a Create covering them, since no test names any of the three recall functions today (ruling 18).
- `src/config/taiknr-config.ts`: the new field, its default and its validation rule. The rest of the type is governed by the `configuration` spec, and `createPiJevScorerAdapter(ctx, config: TaiknrConfig)` keeps its signature.
- `src/app/extension/taiknr.ts`: the placeholder `notifyOnce` removed with the frozen `notifier` member it fed, and reuse of the existing `RecallCache` instance; all seven `register*Handler` calls and their signatures stay (ruling 3).
- New tests beside the layer each exercises: `tests/domain/`, `tests/use-cases/`, `tests/infra/adapters/`, `tests/infra/pi-event-handlers/`, `tests/config/` and `tests/app/extension/`, including at least one session-level test with a scripted classifier. A new live verification script at the repository root, outside the test include and the lint allowlist. No tooling file needs an edit.
- Existing tests this change modifies, each in the same task group as the production change that breaks it, so the gate stays green between groups: `tests/app/extension/taiknr.test.ts` (the event list), `tests/app/extension/handler-gate.test.ts` and `tests/config/session-config.test.ts` (the `TaiknrConfig` literal), `tests/config/taiknr-config.test.ts` (the `toEqual` literal and the rejection rows), `tests/app/extension/archive-session.test.ts` (the shared classifier guard), and `tests/support/fake-pi.ts` (a recording `ui.notify`) (ruling 18; ruling 14).
- Markdown outside this change directory: only in the docs pass, after Michael approves (S11).
- Untouched: the six archive handler files, the archive adapter, `src/domain/archived-output.ts`, the side-store format, `SessionConfig.setEnabled`, the proof-of-concept files, and `~/.pi/agent/` with Joel's sessions.
