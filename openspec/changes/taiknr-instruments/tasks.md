# Tasks

Implementation checklist for `taiknr-instruments`, written to `implementation-readiness-standard.md` from `design.md` (approved; red/green gaps patched), `design-review.md`, `specs/**`, `owner-rulings.md`, `council.md`, `michael-council-rulings.json` and `redgreen-derek.md`.

## How this plan is executed

- **The gate.** Every task ends with `npm run check` (lint → typecheck → test, ADR 0003) green. Formatting is part of it: a hand-wrapped line over 120 columns turns it red, so the only writer is `npx biome check --write .`, never a script in `check`. A check an earlier task made green and a later task touches is run again in that later task; the last group of each capability re-runs its own proofs against the finished code.
- **The baseline.** Before this change `npm run check` is green at **22 test files and 328 tests** — the measurement in ruling 17, taken with `tsconfig.json` carrying `verbatimModuleSyntax` and Biome-formatted. That is the exact baseline count, and it is the number a red-green claim in this plan is measured against; only 1.1 and 1.2, which run before any test is added, name 328, and no later task asserts a total, so a suite that grows correctly never has to be renumbered. `redgreen-derek.md`'s red total of 323 counts collected tests only, because eleven of its files failed at import.
- **The end state** is the design's layout: 15 source and 15 test files created, and 15 files modified (4 source files, `tests/support/fake-pi.ts`, 7 test files, and `package.json`, `package-lock.json` and `tsconfig.json`). After group 14, `tests/**/*.test.ts` holds 37 files: the base's 22 and the 15 created. The spike's 438 tests in 32 files is 22 + 10, because it merged the six publishing-registrar tests into `tests/infra/pi-event-handlers/instruments-events.test.ts`, and its own report says implement should place one file per registrar. Neither total is asserted.
- **Test first.** Each task names the failing behavioral test written before its production code, asserting output or state that fails when the behavior is deleted, with its boundary cases named or `none`. Fakes are external boundaries only — the fake `pi`, the stubbed session manager and context, a recording sink. No test-only branch or hook goes into production code.
- **Red/green labels.** Every test cites the `redgreen-derek.md` label (A1–A12) where it went red and green. Where a test has no label, the task says so and says why; nothing here claims proof the spike did not produce.
- **No model or classifier call.** `npm test` makes none (T22). A test that scripts `classify` gives it its own answers, and a test whose `classify` call would reach pi-ai's classifier takes the shared guard from `tests/support/` (`archive-session.test.ts`, `pi-jev-scorer-adapter.test.ts`); a test that stubs `modelRegistry.classify` on its context stub takes none (`context.test.ts`, `instruments-request.test.ts`); `OPENROUTER_API_KEY` is in the shell of anyone running the suite (AGENTS.md trap; `tail-recall` spec).
- **No Markdown in the diff.** Not one Markdown file other than this `tasks.md` goes in the implementation diff. `README.md`, `ARCHITECTURE.md`, `AGENTS.md`, the ADRs and `docs/` are written in the docs pass after Michael approves the implementation, which the deltas require and no task here does (rulings 20, 21; Joel's standing ruling that documentation never blocks).
- **Logging and errors.** No task adds a log line: the repository has no logger and `src/` holds no `console` call, and D9 adds no reporting channel — log fields: none. The bus adapter's catch is silent, with its `loader.js` comment (D9); every other fault is a throw pi's runner reports on the extension error channel.
- **Names.** Every export, signature and dependency object is in *Interfaces*; nothing else is chosen by the coder.
