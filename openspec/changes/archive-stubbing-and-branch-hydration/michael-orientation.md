## 3. Traps (measured where I could)

1. **`session-start.test.ts` and `fake-pi.ts` will break as soon as `session_start` hydrates.** At `HEAD`, `tests/infra/pi-event-handlers/session-start.test.ts:58` passes `{} as ArchiveStore` (no `replaceAll` method) and `tests/support/fake-pi.ts:31` builds `createContextStub` with only `{ cwd, isProjectTrusted }` (`ctx.sessionManager` is `undefined`). Eight of the eleven existing `session-start.test.ts` cases resolve `enabled: true` and invoke the handler; adding hydration to `session-start.ts` without extending `createContextStub` (e.g., optional `branch?: SessionEntry[]` defaulting to `[]`) and passing an `InMemoryArchiveStore` in `session-start.test.ts` crashes all eight with `TypeError`.
2. **`session_start` is NOT behind `createGatedPi`.** `taiknr.ts:28` passes raw `pi` to `registerSessionStartHandler`. If `session-start.ts` hydrates unconditionally after `loadTaiknrConfig` succeeds, a session configured with `"enabled": false` still hydrates `store` — violating Joel's Q3 ruling (D3) and `configuration-loader/design.md` D5 step 4. Guard hydration on `session.isActive()`.
3. **`agent_before_settle` is skipped on aborted runs, and stale pending items from an abandoned branch blow up the next settlement.** Verified in `agent-session.js:1521` and **measured in `SessionManager.inMemory`**: when a run aborts (`Escape`), `_runBeforeSettleBoundary()` does not run, leaving `pendingOutputs` populated. If the user then navigates `/tree` away from that branch and settles a new run, `appendContextEdit(staleId, ...)` throws `Error: Entry <id> is not on the active branch` (`session-manager.js:983`). Worse, `ExtensionRunner.emitBoundary` (`runner.js:798–813`) validates the whole draft list in `_createBoundaryPreviewManager`; **one throwing `context_edit` sets `valid = false` and discards every draft in that settlement**, while `commitArchivedBatch` already mutated `InMemoryArchiveStore` in memory. Settlement must prune pending items against the active branch **before** committing to `store` (see Q1 and Trap 4).
4. **Pi's retry/overflow recovery omits failed attempts via `context_edit(targetId, null)` — and a later stub `context_edit` resurrects them.** Verified in `agent-session.js:902–935, 2564, 3212` and **measured in `SessionManager.inMemory`**: `_omitRecoveryAttempt` appends `context_edit` with `replacement: null` for a failed assistant turn and its `toolResults`. Because `buildSessionProjection` (`session-manager.js:264`) uses latest-edit-wins, emitting a stub `context_edit` at `agent_before_settle` for a `targetId` whose latest edit on the branch (or in `event.entries`) has `replacement === null` **un-omits the `toolResult` without its omitted `assistant` `toolCall`**, producing an unpaired tool result that fails the next provider request (`agent-session.js:899`, `#11227`).
5. **`event.entries` in `agent_before_settle` is replace-on-return, and empty runs must emit nothing.** Verified in `runner.js:784`: returning `{ entries }` overwrites earlier extensions' boundary drafts unless `[...event.entries, ...drafts]` is returned. Conversely, when a settled run has zero eligible staged items, returning `undefined` (and `toSettlementDrafts([], ...)` returning `[]`) avoids polluting every conversational turn with empty `taiknr-side-store` entries. Also do **not** use `pi.appendEntry()`: `taiknr.test.ts:6–10` uses a `Proxy` that throws on any `ExtensionAPI` property other than `on`, `fake-pi.ts` does not stub `appendEntry`, and `toSettlementDrafts` already returns `CustomEntryDraft` in `SessionBoundaryDraft[]`.
6. **`toolResultEntryIds` is `flatMap`-filtered, and `entryId` is not guaranteed 8 chars.** Verified in `agent-session.js:556–559` and `session-manager.js:21–28`:
   - `generateId` produces 8 hex chars normally, falling back to a 36-char UUID after 100 collisions in `byId`. Treat `entryId` as an opaque non-empty string; never slice to 8 or regex-match 8 hex chars.
   - `toolResultEntryIds = toolResults.flatMap(...)` silently shortens if an ID fails to resolve, so blind `event.toolResultEntryIds[i]` indexing can attach a stub to the **wrong** `toolResult`. **Measured in a live `createAgentSession` probe:** `event.context.contextEntries` on `TurnEndEvent` carries `{ sourceEntry, messages }` with `sourceEntry.message === toolResults[i]` (and matching `toolCallId`), allowing exact `entryId` pairing without changing `toToolOutputCandidates(event, argsByCallId)`'s signature — and `turn-end.ts` must key `originalContentByEntryId` by that exact same `entryId` resolution.
7. **`context_edit` replaces the entire `content` array, and `minCharsToArchive: 0` meets image-only results.** Verified in `session-manager.js:243–254` and **measured in `createAgentSession`**: `projectContextEntry` spreads `{ ...message, content: replacement.content }`. Preserving images requires constructing `[{ type: "text", text: item.stub }, ...nonTextBlocks]` from the original `ToolResultMessage.content` stored in `originalContentByEntryId`. Also, `minCharsToArchive: 0` is a valid gated config (`configuration/spec.md`); on an **image-only** `toolResult` (zero `{ type: "text" }` blocks, `rawText === ""`), `shouldArchive(0, 0)` is `true` — `toToolOutputCandidates` must skip tool results that have no text blocks (or empty text; see O2) so image-only tool outputs do not get bogus empty-text stubs prepended.
8. **`JSON.stringify(event.input)` and `\r` in one-line stubs.** `JSON.stringify(undefined)` returns `undefined` (not `""`), so `.slice(0, 120)` throws `TypeError` on a custom tool with `undefined` input; nested calls (`event.parentToolCallId !== undefined`, `types.d.ts:955`) never produce transcript `toolResults` and leak in `argsByCallId` unless skipped or cleared; and `rawText.split("\n")` on CRLF output leaves literal `\r` inside `preview`, violating the one-line stub contract unless `\r\n` / `\r` are normalized when building the preview and line count.
9. **Fixed-signature & Biome-rule traps in living specs.**
   - `development-checks/spec.md` ("No boundary rule") forbids adding `noRestrictedImports` to `biome.json` unless that spec is modified; hold D6 via code review and a grep/test check rather than editing `biome.json`.
   - `extension-packaging/spec.md` ("Signatures unchanged") locks the 7 handler signatures, existing adapter signatures, and `ports.ts`. Note that `taiknr.ts` itself is **not** locked — if `taiknr.ts` wires anything differently internally while keeping the 7 `register*Handler` calls and signatures intact, `taiknr.test.ts` stays green; if the design adds a new exported helper to `src/infra/adapters/pi-archive-adapter.ts` (for example, to filter active non-omitted branch IDs or extract non-text blocks cleanly outside handler files), check whether `extension-packaging/spec.md` needs a narrow MODIFIED clause or keeps helpers internal/within existing adapter boundaries (O4).
10. **Zero-network session-level testing is measured working in 35 ms.** Chidi left unconfirmed how to attach `fauxProvider` to `createAgentSession`. **Measured in the `$TMP` copy (`npm run check` green — Biome, `tsc --noEmit`, and `vitest`):** `fauxProvider` from `@earendil-works/pi-ai` + `ModelRuntime.create({ modelsPath: null, allowModelNetwork: false, refreshOnCreate: false })` + `modelRuntime.registerNativeProvider(faux.provider)` + `setRuntimeApiKey` + `DefaultResourceLoader` (`extensionFactories: [taiknr, toolHelper]`, `noExtensions: true`) + `SessionManager.inMemory` + `await session.bindExtensions({})` drives `session_start` → `tool_call` → `turn_end` → `agent_before_settle` → `session.navigateTree` (`session_tree`) in ~35 ms with zero network calls and no `package.json` edit. One subtle detail measured: `createAgentSession` appends an initial `{ type: "model_change" }` entry at `getBranch()[0]`, so navigating to a `user` message resets the leaf to its `parentId` (`model_change`), leaving `getBranch()` length 1 rather than 0. (Note: importing `@earendil-works/pi-ai` in `tests/` relies on npm hoisting a transitive dependency of `@earendil-works/pi-coding-agent`; O5 covers whether tests use `fauxProvider` or `ExtensionRunner` / `SessionManager.inMemory` directly without `@earendil-works/pi-ai`.)

## 4. Questions only Joel can answer

**Q1 — What happens to large tool outputs when a run is aborted (`Escape`) and `agent_before_settle` never fires?** (product behavior; card premise Pi 1.5.2 does not satisfy)
Source: Card & ADR 0002 mechanism 1 (*"Across a run ... `agent_before_settle` emits `context_edit` replacements"*, both Janet-drafted) vs Pi 1.5.2 `dist/core/agent-session.js:543, 1521` (`turn_end` fires on `"completed"`, `"aborted"`, and `"error"` turns alike, whereas `_runBeforeSettleBoundary()` is skipped completely whenever `_agentRunAbortRequested` is true, and `ReadonlySessionManager` exposes no `appendContextEdit` outside `turn_end` and `agent_before_settle`).
- **(a) Stage every persisted text tool result meeting `minCharsToArchive` (regardless of `turn_end.outcome`), and carry pending staged items forward to the next settled run — committing only those still on the active branch and not recovery-omitted:** If the user hits `Escape` during a multi-turn tool loop or a runaway `bash` command, those persisted tool results get stubbed and archived as soon as the next run on that branch settles; if the user switches branches via `/tree` first, off-branch staged items are dropped harmlessly instead of crashing settlement (Trap 3). Needs no eighth event handler.
- **(b) Same carry-forward to the next settled run, but stage only when `turn_end.outcome === "completed"`:** Completed earlier turns of an aborted run still get stubbed on the next settle, while partial/aborted-turn tool results stay raw in context permanently.
- **(c) Drop staged items if their own run did not settle:** Any tool output from an aborted run (even completed earlier turns of that run) stays raw and unstubbed in prompt context for the rest of the session.
- **(d) Stub immediately at `turn_end` instead of `agent_before_settle`:** Stubs before an abort can happen, **but** breaks ADR 0002's core premise — rewrites intra-run history mid-loop (invalidating intra-run KV prefix cache and hiding raw tool output from the model while it is still working) and contradicts the `turn-end.ts` / `agent-before-settle.ts` split at `HEAD`.
- **My pick: (a).** Hitting `Escape` on a noisy build or runaway log is one of the commonest ways huge tool outputs enter a Pi transcript, and Pi persists those `toolResults` into future LLM context regardless; carrying them to the next settled boundary (filtered against `getBranch()` and non-null `context_edit`s, Traps 3–4) shrinks them without adding handlers or breaking intra-run prefix caching, and loses nothing if the user quits or branches away first.

**Q2 — Across compactions, should pre-compaction archived outputs stay recallable (`getBranch()`), or should compaction prune them too (`buildContextEntries()`)?** (product behavior & ongoing classifier token spend)
Source: Card & ADR 0002 mechanism 2 (*"hydration runs on `session_start`, `session_tree`, and `session_compact` using `getBranch()` so pre-compaction items remain scorable"*, Janet-drafted from `jev-context-poc.ts:34`, which only hydrated at `session_start`) vs Pi 1.5.2 `dist/core/session-manager.js:201–229, 1074–1084` (Chidi §5).
Why the source rests on a mismatch: Raw `getBranch()` walks `parentId` all the way to root ignoring compaction, so `session_compact` **never changes** which `taiknr-side-store` entries `getBranch()` returns — hydrating from `getBranch()` on `session_compact` is a no-op on an already-hydrated store, and every stub from the start of the branch is sent to Jev on every new prompt until a later cap/pruning card lands. Pi 1.5.2 also exposes `ctx.sessionManager.buildContextEntries()`, which returns `[latest compaction] + entries from firstKeptEntryId onward` (including `custom` entries in the kept and post-compaction range), where `session_compact` **does** prune summarized-away archive batches. Both return `SessionEntry[]`, so neither changes any signature at `HEAD`.
- **(a) `getBranch()` (card / ADR 0002 proposal — keep pre-compaction outputs scorable):** Even after Pi compacts older turns into lossy summary prose, Jev can still recall exact raw outputs (error lines, file paths, config blocks) from earlier in the session. `session_compact` still runs the shared hydration helper (idempotent on normal compaction; self-heals after custom compaction or an off→on toggle). **Cost:** Jev input tokens grow linearly with total branch tool-call history until the separate archive-cap/pruning card ships.
- **(b) `buildContextEntries()` (compaction-bounded archive):** Compaction drops `taiknr-side-store` batches prior to `firstKeptEntryId`, automatically bounding Jev payload and cost at `/compact` and auto-compaction without a separate pruning card, and giving `session_compact` real pruning work. **Cost:** Once older turns are compacted, their raw tool outputs can no longer be recalled on demand.
- **My pick: (a).** Recovering exact lines after older turns leave active context is a primary advantage over compaction alone, and the card already scopes archive caps/pruning separately rather than tying recall lifetime to Pi's compaction cut point. Asking Joel because he bears the per-prompt Jev token cost on long sessions until caps land.

Nothing else is his. Entry ID choice, non-text block preservation, side-store entry type, `enabled: false` inertness, and zero-network testing are settled by prior rulings, code contracts at `HEAD`, or Pi 1.5.2 measurements below.

## 5. Settled vs open

**Settled (for the council and the design):**
- **S1 Item ID is Pi's `entryId`, treated as an opaque non-empty `string`.** `ToolOutputCandidate.entryId` becomes `ArchivedToolOutput.id` (replacing `jev-context-poc.ts`'s `tc_N` counter, which would collide across `/tree` branches). Verified unique per session in `session-manager.js:21–28` and preserved across `/fork` in `session-manager.js:1229–1249`; never slice or assert length 8 (Trap 6).
- **S2 Stub template and `argsSummary` follow `jev-context-poc.ts` + `HEAD` domain types.** `buildStub(candidate)` renders `[archived ${entryId}] ${toolName}(${argsSummary}) status=${isError ? "error" : "ok"} (${rawText.length} chars, ${lines.length} lines) preview: ${preview}` with a 3-line (`" | "`-joined), 180-char head preview, and `tool_call` records `argsSummary` from `JSON.stringify(event.input)` truncated to 120 chars (`jev-context-poc.ts:22–26, 43`; `ARCHITECTURE.md` §11; `test-jev-poc.mjs`'s 2-line/140-char `key=value` strings were hand-written test fixtures, not extension code). Joel may override this; nothing contradicts it. Line-break normalization inside `buildStub`/`argsSummary` is open for council/design (O1).
- **S3 Non-text block preservation via `originalContentByEntryId` and `CustomEntryDraft` at settlement.** `context_edit` is whole-content replacement (Trap 7), so `toSettlementDrafts` builds replacement content combining `{ type: "text", text: item.stub }` with any non-text blocks (`ImageContent`) recorded at `turn_end`, plus one `{ type: "custom", customType: TAIKNR_SIDE_STORE_TYPE, data: batch }` draft when `batch.length > 0`. `agent-before-settle.ts` spreads `...event.entries` before taiknr's drafts and returns `undefined` when nothing commits (Trap 5).
- **S4 Hydration runs on `session_start` (when `session.isActive()`), `session_tree`, and `session_compact` (both gated via `gatedPi`)** through `hydrateArchiveStore(readArchiveBatchesFromBranch(...), store)`, which replaces `store` contents (`replaceAll`) so switching to an empty/clean branch clears stale items. Whether the `SessionEntry[]` input is `getBranch()` or `buildContextEntries()` awaits Q2.
- **S5 `enabled: false` and rejected-config inertness.** Enforced by `createGatedPi` on the five non-`session_start` archive handlers plus an explicit `if (!session.isActive()) return;` before hydration in `session-start.ts` (D3–D5, Trap 2).

No Markdown file other than `tasks.md` lands in Derek's implementation diff.
