## 2. What the change must not touch or foreclose

- **`src/domain/` and `src/use-cases/`** (D5). No config concern enters them; `decisionThreshold` and `minCharsToArchive` already arrive as plain numbers.
- **Exactly seven registrations, one per handler file** (D6, `AGENTS.md`). **Measured:** adding a second `pi.on("session_start", …)` in the composition root turns `tests/app/extension/taiknr.test.ts` red (the sorted list gains a duplicate). A session-time config read has to ride the existing session-start handler, not a new registration.
- **`src/app/extension/taiknr.ts` as the single entry;** no root `index.ts` or `extensions/`.
- **Joel's `~/.pi/agent/` (including any future `pi-taiknr.json` there), `settings.json` and the dotfiles source.** Tests isolate with `mkdtemp` and `PI_CODING_AGENT_DIR` (**measured:** `getAgentDir()` returned `/tmp/fake-agent/pi-taiknr.json` under vitest with the variable set).
- **`biome.json`, `tsconfig.json`, `vitest.config.ts`, `.gitignore`:** nothing in this card needs an edit (D7). `package.json` changes only if the design adopts typebox (Trap 9).
- **`jev-context-poc.ts`, `test-jev-poc.mjs`, the siblings:** untouched, reference only.
- **Do not foreclose the later cards' consumers of config:** `createPiJevScorerAdapter(_ctx, _config: TaiknrConfig)` and both handler deps take a `TaiknrConfig` value. Whatever shape carries a per-session config must still hand those a `TaiknrConfig`.
- **Do not foreclose the `cli/`/`mcp/` entry points (ADR 0001):** keep the loader `(paths) → TaiknrConfig` with no Pi import, so another composition root can call it with its own paths.
- **Do not foreclose env-var overrides (D10):** a loader that merges layers in order leaves room for one more layer; one that selects a single document does not.

## 3. Traps (measured where I could)

1. **No `cwd` and no trust at factory time.** `ExtensionAPI` (`types.d.ts` L1250–1420) exposes neither `cwd` nor `isProjectTrusted`; both live on `ExtensionContext` (L241, L258), which only event handlers receive. `docs/extensions.md` L1183–1201 reads project config inside `session_start` and says to call `ctx.isProjectTrusted()` "before reading project-local extension configuration that should only be honored for trusted projects." Jefferson does both at `session_start` (`startup.ts:51–60`). Pi's own `preset.ts` reads at `session_start` (L397–399) but checks no trust. A factory-time read would use `process.cwd()` and ignore trust.
2. **Config flows by value at factory time today**, into `registerTurnEndHandler` and `registerContextHandler` deps (`taiknr.ts:19,32,42`). With Trap 1, a per-session read must reach those handlers after registration: either the same `TaiknrConfig` object is filled in place at `session_start` (keeps every signature, hides a mutation), or the deps type changes to a holder/getter (explicit, revises D6's signature clause), and the session-start handler gains a config parameter either way. The design must choose explicitly and state the revision; see §5 O1. Measured: a second `session_start` registration is not an escape (see §2).
3. **The card and `ARCHITECTURE.md` §4 hard-code `~/.pi/agent` and `.pi`.** The host exports `getAgentDir()` (honours `PI_CODING_AGENT_DIR`, `config.js` L510–516) and `CONFIG_DIR_NAME` (`pkg.piConfig?.configDir || ".pi"`, L492); docs L1183 say not to hard-code `.pi`. Pi's example, jefferson, pi-llama and pi-ohm all use the helpers.
4. **A value import of the host in the composition root works.** Measured in the copy: `import { CONFIG_DIR_NAME, type ExtensionAPI, getAgentDir } from "@earendil-works/pi-coding-agent"` in `taiknr.ts` → `tsc` 0 errors, Biome clean, entry test green in 268 ms (import 96 %). It falsifies design.md Decision 6's incidental "every Pi import in `src/` is `import type`" (not a spec SHALL) and makes the entry test load the devDependency Pi graph. `src/config/` must not take that import (D5 note); the composition root or an infra adapter resolves paths.
5. **Jefferson is not what the card says.** `configuration.ts:359–369`: the trusted project document *replaces* the agent document whole; `:371–401` and `startup.ts:73`: malformed or rejected files produce a `warning` and the default row, not a thrown error; `startup.ts:52`: non-TUI modes skip everything. So "matching pi-jefferson's precedence rules" + "merges valid fields" + "fail loudly" cannot all be true. → Q1, Q2.
6. **"Fail loudly" means three different things by location.** Factory throw: extension not loaded, startup `Error: Failed to load extension …` (loader.js L519–547). Handler throw: caught per handler in `runner.emit` (`runner.js` L821–848, verified), reported as `Extension "…" error`, the extension stays loaded and other handlers run; the rest of *that* handler is skipped. `ctx.ui.notify(…, "error")`: fire-and-forget, invisible where `hasUI` is false (print, JSON). Only the throw paths are visible in every mode.
7. **JSON edge cases the design must classify** (measured on Node 26.8.1): `""`, `" "` and a BOM-prefixed `{}` throw `SyntaxError`; `[]` and `null` parse without error but are not objects; `"0.5"` is a valid JSON string, not a number. Each is a test row: malformed vs invalid vs root-not-an-object.
8. **Session replacement re-runs everything.** `/new`, `/resume`, `/fork`, `/reload` emit `session_shutdown`, load a replacement extension runtime and emit `session_start` again; `project_trust` can re-run when the cwd changes (`docs/extensions.md` L376–392). A per-session read must be idempotent and re-read on every `session_start`, and `ctx.cwd` may differ from the previous session's.
9. **typebox is host-provided but undeclared.** Pi maps `typebox`, `typebox/compile`, `typebox/value` through jiti (`loader.js` L43–45, L82–83); it sits in `node_modules` transitively (1.3.27) and `packages.md` requires a `peerDependencies: { "typebox": "*" }` entry to use it. Four flat scalar fields; jefferson validates by hand. Not settled; see §5 O2.
10. **Range provenance is in the domain, not the card** (D8): `[0,1]` because the comparand is a probability; `minCharsToArchive ≥ 0` integer because it is a length threshold (0 = archive everything). `defaultDecisionModel`/`defaultDecisionModelProvider` can only be checked as non-empty strings here; registry resolution belongs to the classifier card.

## 4. Questions only Joel can answer

**Q1 — What does a user see, and what does taiknr do, when a config file is present but malformed or invalid?** (product behaviour)
Source: the card's "fail loudly … explicit rejection error" (proposal); jefferson's warn-and-default (`startup.ts:73`, sibling practice); `ARCHITECTURE.md` §7 fail-open (Janet-drafted, about the classifier, not config); Trap 6 for what each surfacing path actually shows.
- (a) **Loud, open to defaults:** `loadTaiknrConfig` throws a clear error naming the file and the field; the extension reports it in a way visible in every mode and runs that session on `DEFAULT_TAIKNR_CONFIG`.
- (b) **Loud, closed:** same report; taiknr does nothing for that session until the file is fixed.
- (c) **Refuse to load:** throw from the factory → `Failed to load extension` at startup. Requires factory-time reading, so it forecloses the trust check (Trap 1).
- **My pick: (a).** The loader still throws (the card's unit-testable criterion holds), the user gets the error in every mode, and the "works out of the box" promise survives one typo; (b) withholds the feature after a single line the user may scroll past; (c) trades Pi's documented trust guidance for a louder message.
- Sub-question, same ruling: **unknown top-level keys** — reject (my pick: a misspelt key is the commonest config mistake and the only one range checks cannot see; jefferson rejects unknown options at `configuration.ts:112`) or ignore (pi-omlx's overlay).

**Q2 — Merge granularity: field-level or whole-document?** (user-facing contract)
Source: card criterion "merges valid fields over `DEFAULT_TAIKNR_CONFIG`" and `ARCHITECTURE.md` §3 (both proposals); Pi's `preset.ts` L70–95 shallow `{…global, …project}`; jefferson `configuration.ts:359–369` whole-document replacement.
- (a) **Field-level:** project fields over agent fields over defaults; a project file states only what differs.
- (b) **Whole-document:** a trusted project file replaces the agent file entirely; a project file must restate everything it wants kept.
- **My pick: (a).** It is what the card's acceptance criterion literally tests, what Pi's own example does, and four flat scalars have no nesting ambiguity; it also leaves room for the env-var layer D10 defers. Choosing (b) means the card's "merges valid fields" clause is dropped; choosing (a) means its "matching pi-jefferson" clause is.

Nothing else is his. The file name, path resolution, trust gating, missing-file behaviour, validation ranges, test layout and wiring scope are settled by rulings or evidence below.

## 5. Settled vs open

**Settled (for the council and the design):**
- **S1 Paths.** Agent file `join(getAgentDir(), "pi-taiknr.json")`, project file `join(ctx.cwd, CONFIG_DIR_NAME, "pi-taiknr.json")` (D3; Pi docs L1183; D2 — every surveyed extension uses the helpers). Resolution lives in the composition root or `src/infra/`, never in `src/config/`; `loadTaiknrConfig(paths: ConfigPaths)` keeps its path-in shape (D5 note; D9). `ARCHITECTURE.md` §4's literal paths go to the docs pass (D4).
- **S2 Missing files are silent.** Either or both absent → `DEFAULT_TAIKNR_CONFIG`, no warning (card, jefferson `:369`, `preset.ts` all agree; no contrary evidence).
- **S3 Validation rules, with provenance (D8, Trap 7).** Root must be a JSON object (`[]`, `null` invalid); `decisionThreshold` a finite number in `[0,1]`; `minCharsToArchive` an integer `≥ 0`; `defaultDecisionModel`, `defaultDecisionModelProvider` non-empty strings; wrong JSON type for a present key is invalid. Every rejection names the file path and the field.
- **S4 Project file honoured only when `ctx.isProjectTrusted()`** (Pi docs L1197–1201; jefferson; `ARCHITECTURE.md` §7 — the provider/model fields decide where stub text is sent). Consequence: config resolves at `session_start` with `ctx`, and is re-read on every `session_start` (Trap 8). Joel may override this; I am not sending it to him because the documentation and the one sibling that reads project config both prescribe it and nothing breaks by honouring it.
- **S5 Wiring is in scope.** `const config = DEFAULT_TAIKNR_CONFIG` (`taiknr.ts:19`) is replaced by the loaded config reaching the turn-end and context deps; an exported `loadTaiknrConfig` with no caller fails Derek's and my "consumer for every export" bar. The card's title and `ARCHITECTURE.md` §4 "loaded at startup" agree.
- **S6 Loader shape.** Synchronous (`readFileSync` + `JSON.parse`; HEAD signature, jefferson, `preset.ts`), no Pi import, throws on malformed or invalid input (card criterion 3) — what the caller does with the throw is Q1.
- **S7 Tests.** `tests/config/taiknr-config.test.ts` with vitest `expect`/`test`, `.js` specifiers, `mkdtemp` directories, no Pi runtime: defaults, agent-only, project-over-agent, each invalid class from S3 and Trap 7, plus the trust-gated and re-read-on-`session_start` behaviours at the composition-root level with the recording fake. Each shown red first (Derek's bar).
- **S8 Scope exclusions stand** (D10), plus: no host settings API exists to use instead (`ExtensionAPI.getSettings()` returns Pi's own settings; issue #4981 unshipped).
- **S9 Docs pass items (minor, D4):** `ARCHITECTURE.md` §3 merge wording to match Q2, §4 paths to S1 and "loaded at startup" to "at each session start"; `AGENTS.md` "the behavior behind them does not" sentence once config behaviour exists; an ADR for config semantics is optional.

**Open for the council and the design:**
- **O1 Carrying a per-session config to handlers registered at factory time** (Trap 2): in-place fill of the shared `TaiknrConfig` object vs a holder/getter in the deps types, and the session-start handler's new parameter. Whichever is chosen, the design names it as a revision of D6's "signatures preserved" clause with its reason; I will accept a narrow, stated revision and reject an unstated one.
- **O2 Validation implementation:** hand-written guards (my lean: four fields, no manifest change, jefferson's approach) vs typebox with a new peer dependency (Trap 9). Decided by the deletion test, not by Joel.
- **O3 How the Q1 error surfaces in every mode** (Trap 6): a throw from the session-start handler is visible in all modes but skips the rest of that handler, so the design must order config resolution against store hydration and say what the handler does after a rejection; `ctx.ui.notify` alone is invisible in print/JSON.
- **O4 Which layer survives a rejection** (pending Q1(a)): defaults for the whole load (one rule) vs falling back to the agent file when only the project file is invalid.
- **O5 Observability:** the session-start handler logs the resolved paths, which files were present and trusted, and the outcome — Derek's bar for a use case entry; where that log goes in a Pi extension is the design's to name.

**Not covered by this pass:** no live Pi session was run (handler-error surfacing is from `runner.js` and docs, not observed); `process.cwd()` vs `ctx.cwd` under the SDK is unverified and unneeded if S4 holds; ecosystem prevalence beyond Chidi's named sample was not surveyed; `test-jev-poc.mjs` and every model-calling path were not run.

Skipped: no measurement of the typebox import under `tsc`/vitest with a peer entry, since O2 leans away from it. Risk: S4 and S5 together force the O1 signature decision — if Joel wants config read once at factory time instead, S4 falls and Q1(c) reopens.
